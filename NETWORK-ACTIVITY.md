Таблица составлена 23 ноября 2026 года. Способ проверки указан в конце документа.

Столбец «Кто соединяется» показывает, чьим кодом открывается соединение: самим расширением, его зависимостью, бинарным компонентом внутри VSIX, VS Code или инструментом на машине пользователя.

## Примечания

- **Телеметрия расширения.** Ключ лежит в `aiKey` манифеста ([package.json](package.json), строка 2062) и имеет формат ключа 1DS. Поэтому библиотека `@vscode/extension-telemetry@0.9.0`, вкомпилированная в расширение, отправляет события запросом `POST https://mobile.events.data.microsoft.com/OneCollector/1.0`. Отправитель создаётся, только когда VS Code сообщает, что включена телеметрия использования или ошибок. При `telemetry.telemetryLevel=off` соединений нет, и то же значение `off` расширение передаёт серверу Roslyn аргументом `--telemetryLevel`. Расширение вызывает только обычные методы отправки (`sendTelemetryEvent`, `sendTelemetryErrorEvent`) и это правило не обходит. В этом репозитории отправитель не создаётся: на его месте в `src/main.ts` стоит заглушка, которая отбрасывает все события и сообщает уровень `off`, поэтому тот же уровень уходит и серверу Roslyn. Библиотека `@vscode/extension-telemetry` в пакет не попадает. Ключ `aiKey` в манифесте остался, но его больше никто не читает: расширение его не использует, а текущий VS Code отправляет телеметрию отладчика только по полю `customTelemetryEndpoint`, которого в манифесте нет.
- **Размеры пакетов.** Прочитаны из заголовка `Content-Length` серверов Microsoft 23 ноября 2026 года. Это размеры сжатых zip-архивов.
- **Загрузка .NET Install Tool.** Проверено 25 ноября 2026 года по исходникам последнего релиза `Runtime-v2.3.3` на GitHub (вышел 15.04.2025), скрипту установки и ответам серверов; само расширение C# требует версию не ниже 2.2.3. В этом репозитории инструмент не объявлен зависимостью пакета и ставится вручную: если его нет или он старее 2.2.3, расширение C# показывает сообщение об ошибке без кнопок и не активируется. Другая версия зависимости может вести себя иначе. В этом репозитории расширение обращается к инструменту только командой `dotnet.findPath`: переход к загрузке и к установке библиотек Linux отключён флагом `downloadDotnet = false`, сам код остался. Перед вызовом расширение само активирует инструмент (`activateDotNetRuntimeExtension` в `dotnetRuntimeExtensionResolver.ts`): инструмент больше не объявлен зависимостью пакета, VS Code не запускает его первым, и без этого при старте с открытым проектом команда `dotnet.findPath` ещё не зарегистрирована. `dotnet.findPath` — только локальный поиск, в таком порядке: путь из настроек инструмента `dotnetAcquisitionExtension.sharedExistingDotnetPath` или `existingDotnetPath` (полный путь к исполняемому файлу `dotnet`), `dotnet` в оболочке входа, `PATH`, `DOTNET_ROOT`, записи установщика (`/etc/dotnet/install_location_*`, в Windows — реестр). Подходит путь, у которого совпадает архитектура и есть `Microsoft.NETCore.App` не ниже 10.0.5 без предпросмотров (с Dev Kit нужен ещё `Microsoft.AspNetCore.App`); такой путь инструмент отдаёт первым, и расширение загрузку не запускает. Неподходящий путь из настройки игнорируется с предупреждением, поиск продолжается, а при неудаче возможно скачивание: настройки «не скачивать» нет. Выпуск, уже скачанный инструментом, отдаётся по `dotnet.acquireStatus` без загрузки. `dotnet.acquire` работает в три шага: скачивает индекс выпусков (7 КБ, кэш 5 минут), скачивает скрипт `dotnet-install.sh` (64 КБ) или `dotnet-install.ps1` (75 КБ), затем скрипт с точной версией качает архив runtime в папку хранилища инструмента. Всё это — `builds.dotnet.microsoft.com`; у скрипта есть запасной адрес `ci.dot.net/public`. Расширение запрашивает `10.0`, инструмент берёт последний выпуск канала; проверку контрольной суммы в текущем скрипте я не нашёл. При таймауте запроса инструмент делает DNS-запрос `www.microsoft.com`. На Linux после загрузки вызывается `dotnet.ensureDotnetDependencies`: инструмент пробно запускает сервер и, если тот завершился с сигналом, предлагает установить `libicu`, `libkrb5-3`, `zlib1g` и другие библиотеки (список зависит от дистрибутива) через `apt-get`, `yum`, `zypper`, `pacman`, `eopkg` или `apk` с правами администратора — только после нажатия «Install» в диалоге. Телеметрия инструмента отправляется при каждой его операции, если включены и телеметрия VS Code, и настройка `dotnetAcquisitionExtension.enableTelemetry`; адрес — из `connectionString` манифеста инструмента. Выключение этой настройки заставляет инструмент выставить `DOTNET_CLI_TELEMETRY_OPTOUT=true`.
- **Запуск тестов.** Без C# Dev Kit команды «Run Tests in Context» и «Debug Tests in Context» отправляют серверу Roslyn запрос `textDocument/runTests`; сервер находит в SDK `vstest.console.dll` через `dotnet --info` и запускает его. В тестовой платформе SDK 10.0.400 нет адресов телеметрии: они есть только в самом `dotnet` (команда `dotnet test`), который сервер не запускает. На проверке в песочнице консоль тестирования запустилась и ни к чему не обратилась; полноценный прогон тестов не проводился.
- **Состав пакета.** Кроме отладчика, сервера Roslyn и моста в пакет попадают `.xamlTools` (10,7 МиБ), `.testDiscovery` и `.roslynDevKit`. Расширение передаёт их серверу только при установленном C# Dev Kit; в этой сборке они не загружаются. Адресов телеметрии в них нет.
- **Что осталось непроверенным.** Загрузка runtime, установка библиотек Linux и телеметрия инструмента проверены по исходникам, а не запуском; то же относится к загрузке символов и исходников по Source Link у отладчика: отладочную сессию провести не удалось, отладчик разрешает запускать программу только из Visual Studio Code. Собственные обращения C# Dev Kit и Copilot по исходникам не видны: их подтвердит только анализ трафика готовой сборки.

## Как проверялось

- **Код расширения** — по исходникам этого репозитория: поиск сетевых примитивов, вызовов API VS Code, запускаемых процессов и адресов в манифесте.
- **Телеметрия** — по пакетам `@vscode/extension-telemetry@0.9.0` и его зависимостям в версиях из `package-lock.json`; контрольные суммы пакетов совпали.
- **.NET Install Tool** — по исходникам тега `Runtime-v2.3.3` репозитория `dotnet/vscode-dotnet-runtime`.
- **Отключение телеметрии в этом репозитории** — 24 ноября 2026 года: бандл из собранных пакетов сверен с прежним. Адрес `mobile.events.data.microsoft.com` и путь `OneCollector` из него исчезли, ключ `aiKey` больше не читается, заглушка на месте. Поведение VS Code с полем `aiKey` сверено с исходниками VS Code на ветке `main`. Запуск расширения в VS Code с этой правкой не проверялся.
- **Встроенный `VSWebAssemblyBridge` в этом репозитории** — 24 ноября 2026 года: пакеты распакованы, и код активации (`installRuntimeDependencies`) для каждого пакета на своей платформе не находит ничего, что нужно скачивать. В пакете без встроенного моста та же проверка показывала его загрузку. Запуск расширения в VS Code не проверялся.
- **Требование `RoslynCopilot` убрано в этом репозитории** — 24 ноября 2026 года: строки требования больше нет в бандле всех четырёх пакетов, код активации на распакованных пакетах не находит ничего, что нужно скачивать. Сценарий с установленным C# Dev Kit в VS Code не проверялся.
- **Режим OmniSharp отключён в этом репозитории** — 24 ноября 2026 года: настоящая функция активации запущена в модульном тесте с включённой настройкой `dotnet.server.useOmnisharp` и без C# Dev Kit.
