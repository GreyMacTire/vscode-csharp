## Примечания

- **Телеметрия расширения.** Ключ лежит в `aiKey` манифеста ([package.json](package.json), строка 2062) и имеет формат ключа 1DS. Поэтому библиотека `@vscode/extension-telemetry@0.9.0`, вкомпилированная в расширение, отправляет события запросом `POST https://mobile.events.data.microsoft.com/OneCollector/1.0`. Отправитель создаётся, только когда VS Code сообщает, что включена телеметрия использования или ошибок. При `telemetry.telemetryLevel=off` соединений нет, и то же значение `off` расширение передаёт серверу Roslyn аргументом `--telemetryLevel`. Расширение вызывает только обычные методы отправки (`sendTelemetryEvent`, `sendTelemetryErrorEvent`) и это правило не обходит. В этом репозитории отправитель не создаётся: на его месте в `src/main.ts` стоит заглушка, которая отбрасывает все события и сообщает уровень `off`, поэтому тот же уровень уходит и серверу Roslyn. Библиотека `@vscode/extension-telemetry` в пакет не попадает. Ключ `aiKey` в манифесте остался, но его больше никто не читает: расширение его не использует, а текущий VS Code отправляет телеметрию отладчика только по полю `customTelemetryEndpoint`, которого в манифесте нет.
- **Размеры пакетов.** Прочитаны из заголовка `Content-Length` серверов Microsoft 23 ноября 2026 года. Это размеры сжатых zip-архивов.
- **Загрузка .NET Install Tool.** Адреса проверены по исходникам последнего релиза `Runtime-v2.3.3` на GitHub; само расширение C# требует версию не ниже 2.2.3. В этом репозитории инструмент не объявлен зависимостью пакета и ставится вручную: если его нет или он старее 2.2.3, расширение C# показывает сообщение об ошибке без кнопок и не активируется. Другая версия зависимости может вести себя иначе. `dotnet.findPath` — только локальный поиск. `dotnet.acquire` работает в три шага: скачивает метаданные выпусков, скачивает скрипт `dotnet-install.sh`, затем скрипт качает архив runtime. Всё это — `builds.dotnet.microsoft.com`. При сбое установки зависимость делает DNS-запрос `www.microsoft.com`. Собственная телеметрия зависимости идёт на адрес из строки подключения в её манифесте.
- **Что осталось непроверенным.** Адрес скрипта установки для Windows (`dotnet-install.ps1` скачать не удалось), установщик системных библиотек Linux и поведение телеметрии самой зависимости. Собственные обращения сервера Roslyn, отладчика vsdbg, C# Dev Kit и Copilot по исходникам не видны: их подтвердит только анализ трафика готовой сборки.

## Как проверялось

- **Код расширения** — по исходникам этого репозитория: поиск сетевых примитивов, вызовов API VS Code, запускаемых процессов и адресов в манифесте.
- **Телеметрия** — по пакетам `@vscode/extension-telemetry@0.9.0` и его зависимостям в версиях из `package-lock.json`; контрольные суммы пакетов совпали.
- **.NET Install Tool** — по исходникам тега `Runtime-v2.3.3` репозитория `dotnet/vscode-dotnet-runtime`.
- **Отключение телеметрии в этом репозитории** — 24 ноября 2026 года: бандл из собранных пакетов сверен с прежним. Адрес `mobile.events.data.microsoft.com` и путь `OneCollector` из него исчезли, ключ `aiKey` больше не читается, заглушка на месте. Поведение VS Code с полем `aiKey` сверено с исходниками VS Code на ветке `main`. Запуск расширения в VS Code с этой правкой не проверялся.
- **Встроенный `VSWebAssemblyBridge` в этом репозитории** — 24 ноября 2026 года: пакеты распакованы, и код активации (`installRuntimeDependencies`) для каждого пакета на своей платформе не находит ничего, что нужно скачивать. В пакете без встроенного моста та же проверка показывала его загрузку. Запуск расширения в VS Code не проверялся.
- **Требование `RoslynCopilot` убрано в этом репозитории** — 24 ноября 2026 года: строки требования больше нет в бандле всех четырёх пакетов, код активации на распакованных пакетах не находит ничего, что нужно скачивать. Сценарий с установленным C# Dev Kit в VS Code не проверялся.
- **Режим OmniSharp отключён в этом репозитории** — 24 ноября 2026 года: настоящая функция активации запущена в модульном тесте с включённой настройкой `dotnet.server.useOmnisharp` и без C# Dev Kit. Требуются `Debugger`, `Razor`, `VSWebAssemblyBridge`, запускается сервер Roslyn; до правки тот же тест требовал `OmniSharp` и запускал `activateOmniSharp`. Запуск в VS Code не проверялся. В тот же день сервер `roslynomnisharp.blob.core.windows.net` отвечал `HTTP 403` на анонимные запросы к архивам OmniSharp.
- **.NET Install Tool больше не зависимость пакета** — 24 ноября 2026 года: в манифестах всех четырёх собранных пакетов поле `ExtensionDependencies` пустое. Настоящая проверка версии запущена в модульном тесте: без установленного инструмента до правки активация падала с `TypeError`, после — показывает сообщение о том, что нужна версия не ниже 2.2.3, и не активируется. Установка инструмента вручную и запуск в VS Code не проверялись. 25 ноября 2026 года кнопка «Update and reload» убрана: в том же тесте сообщение выходит без кнопок, а команды установки и перезагрузки не выполняются; вызова `workbench.extensions.installExtension` в бандлах четырёх пакетов нет.
- **Загрузка отладчика в этом репозитории** — 25 ноября 2026 года: в пакетах всех четырёх платформ в `.debugger` лежит 308–616 файлов отладчика и `install.Lock`; по этому файлу код активации пропускает пакет. 24 ноября тот же код (`installRuntimeDependencies`) на распакованных пакетах каждой платформы не находил ничего, что нужно скачивать.
- **Restore пакетов** — 25 ноября 2026 года: в бинарнике сервера найдена команда `dotnet restore`. Сама команда (SDK 10.0.400) запущена в изолированном окружении без сети: проект без библиотек и проект с библиотекой из локальной папки восстанавливаются; при уже скачанных библиотеках restore проходит, но с предупреждением `NU1900` (обращение к источнику за данными об уязвимостях), а с выключенным свойством `NuGetAudit` проходит без него; если библиотеки нет и источник недоступен — ошибка `NU1301`. Без источников (пустой `<clear />` в пользовательском `nuget.config`) restore проходит по локальному кэшу без предупреждений, а без нужной библиотеки сразу даёт ошибку `NU1100`; без такого файла SDK при первом запуске сам создаёт пользовательский конфиг с `nuget.org`, одного конфига на уровне машины для этого мало. Restore из расширения в VS Code не запускался.
- **Автозапуск restore выключен по умолчанию в этом репозитории** — 25 ноября 2026 года: умолчание `dotnet.projects.enableAutomaticRestore` в `package.json` сменено на `false`. Настоящий сервер из пакета linux-x64 запущен без сети под видом редактора (клиент LSP вместо VS Code) с проектом, у которого нет скачанных пакетов. Сервер запрашивает у редактора настройку под именем `projects.dotnet_enable_automatic_restore`, расширение переводит его в `dotnet.projects.enableAutomaticRestore`. При ответе `false` restore не запускается и файл `obj/project.assets.json` не создаётся; при `true` и без значения сервер выполняет `dotnet restore` командой `dotnet` из `PATH`, и файл создаётся. Значение из `package.json` редактору возвращает сам VS Code; в работающем VS Code не проверялось.
- **SourceLink** — 25 ноября 2026 года: тот же сервер из пакета linux-x64 запущен тем же способом; проект ссылался на библиотеку, в символах которой записана ссылка SourceLink на локальный веб-сервер. Сервер запрашивает настройку под именем `navigation.dotnet_navigate_to_source_link_and_embedded_sources`. При ответе `true` и встроенном в символы исходнике сервер показал оригинальный исходник, при `false` — восстановленный код. Когда в символах была только ссылка SourceLink, сервер при `true` и без значения показал восстановленный код, и веб-сервер не получил ни одного запроса, в том числе когда папка `.debugger` передана аргументом `--extension`. По исходникам Roslyn скачивание и поиск символов на серверах символов идут через службу отладчика (`ISourceLinkService`). С установленным C# Dev Kit и в самом VS Code не проверялось.
- **JSON-схемы вложены в пакет в этом репозитории** — 25 ноября 2026 года: четыре схемы скачаны с `schemastore.org` (итоговый адрес `www.schemastore.org`, суммарно 61 КБ) и лежат в папке `schemas`; адреса в `package.json` заменены на `./schemas/…`. По исходникам VS Code адрес, начинающийся с `./`, разрешается в папке расширения. Схемы не ссылаются ни наружу, ни друг на друга; проверщик схем принимает корректный образец файла и отклоняет структурно неверный для всех четырёх (у схемы `omnisharp.json` ограничения на отдельные значения слабые, таков исходный файл). В пакетах всех четырёх платформ файлы схем побайтно совпадают с репозиторием, удалённых адресов в манифестах не осталось. Файлы — точные копии того, что хранилище отдавало в день проверки, дальше они не обновляются; лицензия схем в каталоге хранилища не указана. Подсказки по локальным схемам в работающем VS Code не проверялись.
